\section{Case study: Asynchronous Byzantine Agreement}

This section is a case study: the verification of an implementation of
Asynchronous Byzantine Agreement against a small specification, by
probabilistic forward simulation, built on the five results proved above.
The setting is $n$ processes, each holding an input bit, of which at most $f$
are Byzantine, with $3f < n$, communicating by asynchronous message passing.
The development lives in the opt-in \texttt{Leslie2Protocols} Lake library.

\subsection{Setting and conventions}

Three protocols occur in the case study.
Each is given as a list of properties over the calls and returns of its
interface.
A property speaks only of \emph{correct} processes, that is, of processes
that are never corrupted.

Asynchronous Byzantine Agreement (ABA).
Processes start with a bit in $\{0,1\}$ and may return a bit.
\begin{itemize}
  \item Validity: if a correct process returns $b$ then a correct process had
    $b$ as input.
  \item Agreement: if two correct processes return, then their outputs are
    equal.
  \item $\varepsilon$-sure Termination: if $n-f$ correct processes take part in
    the protocol then, with probability $1-\varepsilon$, all correct processes
    will eventually return.
\end{itemize}

Graded Binding Crusader Agreement (GBCA).
Processes start with a binary input in $\{0,1\}$ and may return a value in
\[
  \{(0,A),\ (0,B),\ (\bot,C),\ (1,B),\ (1,A)\}.
\]
\begin{itemize}
  \item Validity: if a correct process does not return $(b,A)$ then a correct
    process had $1-b$ as input.
  \item Graded Agreement: if two correct processes return $(b,X)$ and
    $(b',X')$ then $b = 0 \Rightarrow b' \neq 1$ and
    $X = A \Rightarrow X' \neq \bot$.
  \item Binding: when a correct process returns then a bound value $b$ is
    defined and, in all extensions of the execution, correct processes do not
    return $(1-b,B)$ or $(1-b,A)$.
  \item Termination: if $n-f$ correct processes take part in the protocol then
    all correct processes will eventually return.
\end{itemize}
In the second clause of Graded Agreement the symbol $\bot$ stands in the grade
component, where the return domain admits only $A$, $B$ and $C$.
It is read here as the grade $C$, the sole grade paired with the value $\bot$.
The encoding realises that reading: an $A$-return and a $C$-return of the same
instance exclude one another.
The bound value of the Binding clause is realised by its complement: the
specification carries the set of bits it can no longer hand out, and the
clause's $1-b$ is a member of that set (D19).

Weak Common Coin (WCC).
Processes start with no input and may return a bit.
\begin{itemize}
  \item $\varepsilon$-Goodness: with probability $\varepsilon$, all correct
    processes return $0$ (resp.\ $1$).
  \item Unpredictability: until $f+1$ processes have called WCC, all outcomes
    are still possible.
  \item $(1-\failmass)$-sure Termination: if $n-f$ correct processes take part in
    the protocol then, with probability $1-\failmass$, all correct processes will
    eventually return.
\end{itemize}

What this development establishes is Validity and Agreement for ABA,
machine-checked.
What it does not establish is the rest.
Termination, Unpredictability and fairness are out of scope.
The weak common coin is held at specification level rather than implemented:
its own implementation over Gather and SRSD is not modelled here, so
$\varepsilon$-Goodness enters as an assumption.

Every protocol $P$ with sub-protocols $Q$ is treated in two moves.
The first move is substitution: in a fixed context, each sub-implementation is
replaced by the corresponding specification, which is sound by precongruence.
The second move is the core simulation: the core algorithm of $P$ composed with
the specifications of its sub-protocols is simulated by the specification of
$P$.
Composing the inclusions places the implementation of $P$ inside the
specification of $P$.
The recursion stops at GBCA, which is carried to implementation level.
GBCA calls no sub-protocol, so no further substitution arises there.
WCC is left at specification level.
The subject of the argument is the system as deployed: $n$ programs beside a
network adversary and a coin oracle, given in that form in
Section~\ref{sec:aba-perproc} --- one automaton per process, carrying that
process's round loop and its graded-agreement stage at every round and nothing
that names corruption, and one automaton holding the message pools, the
corrupted set and the corruption budget.
Substitution needs the layer it replaces to be a component, so the first step
of the argument re-cuts that system along its layer boundaries, which is a
change of partition and not of system
(Theorem~\ref{thm:aba-exploded-atd}).
The substitution then runs in those coordinates, and one further repartition
puts the result in the shape the hand-built core simulation is written
against.

These names are used throughout this section and follow the numbering of the

Of those two only the ABA core is reproduced here.
The cited paper carries a third, independent numbering, always written here

The GBCA implementation this chapter displays and encodes is ABDY22's

A cross-reference of the form ``Algorithm~\ref{alg:aba-core}'' always points to

\paragraph{Deviations.}
The encodings depart from~\cite{LeslieBP} in catalogued ways.
Each departure carries a label D1--D19 and is cited at the point where it
applies.
The labels D2, D6 and D7 are unused.
\begin{itemize}
  \item D1: corruption is a total deterministic transform.
  \item D3: the re-propose guard on rule~7 of Transition System~1.
  \item D4: the WCC \texttt{guess} label and the \texttt{guess} state field are
    omitted.
  \item D5: a set-based authenticated network with per-sender message pools.
  \item D8: protocol sends gated on prior participation.
  \item D9: $0$-based round indexing.
  \item D10: the per-round bookkeeping between the coin return and the next
    call fused into the $retW$ step, which multicasts DECIDED on an $A$ grade.
  \item D11: Byzantine call- and return-driver rules at each handshake.
  \item D12$'$: per-process DECIDED sent and received pools, delivery per
    (receiver, sender, bit), and Byzantine equivocation at that layer.
  \item D13: the Validity provenance apparatus on Transition System~1, namely a
    ghost record of genuine calls, an $f+1$ support guard on the mixed-bind
    rule, a provenance guard on re-proposal, and a Byzantine fill rule.
  \item D14: $f+1$ support guards on the GBCA specification's binding, on the
    dissenting bit at its $B$-return, and on each of the two bits at its
    $C$-return.
  \item D15: the $F$-blind form of those support counts, namely $f+1$ distinct
    callers-or-corrupted.
  \item D16: the two-phase abstract twin used by the core simulation.
  \item D17: a fourth outcome $\dagger$, of mass $\failmass$, on the single
    distribution both coin resolutions follow, rule~5 of Transition System~1 and
    rule~3 of Transition System~3.
    It carries the delivery failure of the $\varepsilon$-correct secret-sharing
    coin implementation that the source builds on, where both of the source's
    resolutions range over $\{0,1,\top\}$ only.
    A $\dagger$ round of Transition System~3 enables no return.
    A $\dagger$ round of Transition System~1 is frozen: no process adopts the
    bound value and none re-proposes.
  \item D18: the GBCA implementation transcribes ABDY22's Algorithm~6 in full
    --- six rounds, the message levels INPUT, ECHO, VOTE, BIND and SEAL, and
    the decide conditions of that algorithm --- in place of the source
    blueprint's Algorithm~2, which is a four-round compression of it.
    The compression elides the SEAL level, reads the three decide conditions
    one message level down, and takes $f{+}1$ $\mathrm{VOTE}\,v$ receipts as
    the grade-$1$ witness where Algorithm~6 takes $f{+}1$ $\mathrm{BIND}\,v$
    receipts.
    That compression violates Binding.
    One process held at the echo stage through a $C$-return may afterwards
    direct its write-once echo at either bit, and a single corruption completes
    the $f{+}1$ $\mathrm{VOTE}\,v$ count for the bit the adversary picks, so two
    extensions of one $C$-return hand out two different bits and no
    binding-faithful specification simulates the compression.
    The source blueprint carries a matching red annotation at those decide
    conditions.
  \item D19: the GBCA specification state carries an exclusion set
    $dead \subseteq \{0,1\}$, the bits the instance can no longer hand out, in
    place of the source's bound value $bind \in \{0,1,\bot\}$.
    The set is the killed-bit reading of that value.
    Its only writer is the internal binding transition, which fires from
    $dead = \emptyset$ alone, so every reachable state has $dead = \emptyset$ or
    $dead = \{b\}$ for one bit $b$, and the bound value embeds onto exactly
    those states, $bind = \bot$ as $dead = \emptyset$ and $bind = b$ as
    $dead = \{1-b\}$.
    The two state shapes therefore differ in the guards rather than in the
    cardinality.
    The source's guard $bind = v$ on the value-bearing returns becomes the pair
    $v \notin dead$, $1-v \in dead$; its guard $bind = \bot$ on binding becomes
    $dead = \emptyset$; and the $C$-return's binding obligation
    $bind \neq \bot$, which in the source also puts the bound value on the
    return label, becomes $|dead| \ge 1$, read off a label that names no bit.
    Binding is thereby negative and monotone --- the internal transition adds
    one bit and no rule removes one --- which makes Graded Agreement and Binding
    structural rather than invariants of the specification
    (Theorem~\ref{thm:gbca-spec-binding}) and carries the safety half of
    Validity (Theorem~\ref{thm:gbca-spec-validity}).
\end{itemize}

\paragraph{Outside the model.}
Two features of~\cite{LeslieBP} are deliberately not encoded.
The first is fairness: the source marks each transition fair or unfair, and a
fair execution is one that is finite and ends in a fair deadlock or contains
infinitely many fair transitions.
The second is partial information: the source carries adversaries given by a
pair of observation functions on states and on labels, together with the belief
construction that turns such an adversary into an omniscient one on a derived
system.
Neither appears here.
Every adversary in this section is omniscient, so the observation functions are
the identity and the belief construction is not needed.
The fairness markings bear only on liveness, which is out of scope.

\paragraph{Notation.}
Write $[n]$ for the identifier set and $F \subseteq [n]$ for the corrupted set.
The quorum predicate is
\[
  |\{ id \in [n] \setminus F : call[id] \neq \bot \} \cup F| \ \geq\ n - f .
\]
Values range over $\{0,1,\bot,\top,\dagger\}$, the type \leandecl{PLTS.ABA.TVal}, where $\bot$ is unresolved,
$\top$ is an adversarially resolved outcome, and $\dagger$ is a resolution that

The cross-domain equality $agrees$, \leandecl{PLTS.ABA.TVal.agrees}, holds of $\bot$ with $\bot$ and of $b$ with
$b$.
Both $\top$ and $\dagger$ agree with nothing.

A Dirac target and a genuinely probabilistic one are therefore distinguishable

\subsection{The system as deployed}
\label{sec:aba-perproc}

What runs is $n$ programs, a network adversary and a coin oracle.
Each program is one process: its round loop, its graded-agreement stage at every
round, and the messages that have been delivered to it.
It is corruption-blind.
No field of its node is a copy of the corrupted set, none is a corruption flag,
and none records what the process has multicast, so no guard of its rule table
can ask whether the process is honest or what it has sent.
The network adversary holds exactly what a process may not see: the message
pools of every sender, the DECIDED pools, and the corrupted set together with
the corruption budget.
It takes part in every send, in every delivery, and in every authorisation of
off-protocol behaviour.
The coin oracle is the weak common coin, which this development holds at
specification level (Transition System~3).
Two implementation layers make up the programs, and this section gives them in
the form they run in: the pseudocode of one process, then the automaton of one
process, every guard of which reads that process's own node, and then the
adversary that holds the rest.
The two subsections after this one give the same two layers a second time, as
rule inventories over the whole system state, in which a guard is read against
the line of pseudocode it transcribes.
Each of those inventories is one automaton where the programs are $n$, and each
enters the argument at a named point.
The graded-agreement inventory is what one round of the deployed protocol
projects onto, which is how the refinement proved of it transports
(Theorem~\ref{thm:aba-subsim}).
The round-loop inventory is a factor of the composition the core simulation is
written against, reached from the deployed shape by a repartition of state
(Theorem~\ref{thm:aba-flatspec-spec}).
The forms name one system in each case, and the choice between them fixes only
which state a rule is written to read.

What a process knows about corruption is nothing.
No honest rule of either layer reads the corrupted set, and each Byzantine rule
asks only whether the process it belongs to is corrupted --- a question about
what the environment may do, not about the process's own data.
The program below therefore carries neither that set nor a bit standing in for
it, and the question is answered where the answer lives: at the network
adversary, whose guard $k \in F$ is the whole authorisation of an off-protocol
step.

What the program does carry is the local effect of such a step.
A driven call opens the process's stage record exactly as an honest call would,
and a driven return marks that record returned under the same receipt evidence.
The sub-protocol ports are input-enabled in that sense: a process can refuse
neither a call nor a return, and cannot tell an authorised one from an honest
one.
Only the choice of which drives are available is the environment's.

The three components are composed by full synchronisation, communicating
through send, delivery and drive labels that the composition hides.
The programs are composed by the product of Definition~\ref{def:syncproduct},
taken over the extended alphabet of Definition~\ref{def:relabel} and read back
along the restriction that definition supplies.
The node of one automaton holds that process's records and its inbox rows and
nothing further, so locality sits in the state shape and not in the guards
alone.

\dynamics{What is distributed and what is not}{%
Calling the encoding a distributed algorithm is a claim about which state a
rule is allowed to read, and the presentation states it in its sharpest form.
Every implemented part of the protocol is $n$ programs: the round loop, the
graded-agreement stage of each round, the DECIDED gossip and the receipt
bookkeeping of both layers sit inside $\mathrm{ABAProcN}(P,j)$, and every guard
of its forty-four rules is a function of $j$'s node.
Nothing of the protocol is shared.
The receipt rows and the control records each belong to one process, every
quorum count is taken over one node's rows, and a process knows nothing at all
about corruption --- not even its own status, which no guard of its table can
name.
Two components are not programs, and each is centralized for its own reason.
The first is the network adversary.
It is not part of the protocol: it is the environment the protocol runs in, and
it holds what a process is not entitled to see --- who has multicast what, who
is corrupted, and how much corruption is left.
Putting the message pools there rather than in outboxes is what makes a
process's blindness to its own sends structural, and putting the corrupted set
there with its guard $k \notin F \wedge |F| < f$ makes the corruption budget a
component's guard rather than a side condition on the executions the adversary
may produce.
The second is the coin oracle, and it is centralized of necessity.
An $\varepsilon$-common coin is a correlation between processes: the assumption
is that with probability at least $\varepsilon$ the processes of a round read the
same bit.
A correlation is not a property of any one process's state, so no assignment of
the oracle's transitions to per-process rules expresses it.
Writing the oracle as $n$ programs would mean supplying the protocol that
produces the correlation, which is the layer this development assumes rather
than proves.
It is also the one factor whose transitions are not Dirac, and it occupies the
same coordinate in every system of the argument, from the deployed protocol to
the composition the core simulation runs on.
}

\subsection{The graded-agreement stage}

\input{nodes/def-aba-gbca-impl}

The Lean encoding of Algorithm~\ref{alg:gbca-impl} is the round-$r$ instance
$\mathrm{GBCA.implInst}$, an LTS over the shared label alphabet of the
development.
Fix the parameters $n$ and $f$ with $3f < n$.
Write $[n]$ for the process identifiers and $F \subseteq [n]$ for the corrupted
set.
The message type is
\[ \begin{aligned}
     \mathrm{Msg} \;=\;
     &\{\,\langle\mathrm{INPUT}, b\rangle,\ \langle\mathrm{ECHO}, b\rangle
       \;:\; b \in \{0,1\}\,\}\\
     &{}\cup\;
     \{\,\langle\mathrm{VOTE}, v\rangle,\ \langle\mathrm{BIND}, v\rangle,\
       \langle\mathrm{SEAL}, v\rangle \;:\; v \in \{0,1,\bot\}\,\}.
   \end{aligned} \]
Every rule of the instance is Dirac.
A rule is therefore determined by its guard and its state update, and the table
below carries no distribution column.

The local state of one process is the record $\mathrm{ProcState}$, \leandecl{PLTS.ABA.GBCA.ProcState}, with fields
\begin{itemize}
  \item $\mathit{input}$ --- the bit supplied by the environment call; unset
    before the call.
  \item $\mathit{sentInput} : \{0,1\} \to \{\text{true},\text{false}\}$ --- which
    $\mathrm{INPUT}$ payloads this process has multicast.
  \item $\mathit{sentEcho}$ --- the $\mathrm{ECHO}$ payload multicast; unset if
    none, and written at most once.
  \item $\mathit{sentVote}$ --- the $\mathrm{VOTE}$ payload multicast; unset if
    none, and the recorded payload may itself be $\bot$.
  \item $\mathit{sentBind}$ --- the $\mathrm{BIND}$ payload multicast, on the
    same convention.
  \item $\mathit{sentSeal}$ --- the $\mathrm{SEAL}$ payload multicast, on the
    same convention.
  \item $\mathit{returned}$ --- whether this process has returned from the
    instance.
\end{itemize}
The state of the instance is the record $\mathrm{ImplState}$, \leandecl{PLTS.ABA.GBCA.ImplState}, with fields
\begin{itemize}
  \item $\mathit{proc} : [n] \to \mathrm{ProcState}$ --- the local states.
  \item $\mathit{sent} : [n] \to \mathcal{P}(\mathrm{Msg})$ --- $\mathit{sent}(j)$
    is the set of messages $j$ has multicast (D5).
  \item $\mathit{recv} : [n] \times [n] \to \mathcal{P}(\mathrm{Msg})$ ---
    $\mathit{recv}(i,j)$ is the set of $j$'s messages the adversary has delivered
    to $i$ (D5).
  \item $F$ --- the corrupted set, held in lockstep with the other components by
    the $\mathrm{fail}$ broadcast.
\end{itemize}
Multicasts are idempotent and thresholds count distinct senders, so message
duplication and point-to-point scheduling are absorbed into the set model (D5).
Three derived quantities occur in the guards.
Set
\[
  \#_i(m) \;=\; |\{\, j \in [n] \;:\; m \in \mathit{recv}(i,j) \,\}|,
  \qquad
  \mathit{Val}_i \;=\;
    \{\, b \in \{0,1\} \;:\; \#_i(\langle\mathrm{INPUT}, b\rangle) \ge n - f \,\},
\]
and write $\#_i(\mathrm{EC})$, $\#_i(\mathrm{VT})$, $\#_i(\mathrm{BD})$,
$\#_i(\mathrm{SL})$ for the payload-blind counts, that is, the number of
distinct senders from which $i$ holds some $\mathrm{ECHO}$, some
$\mathrm{VOTE}$, some $\mathrm{BIND}$, some $\mathrm{SEAL}$.
The set $\mathit{Val}_i$ is Algorithm~\ref{alg:gbca-impl}'s variable
$\mathit{Valid}$, read off the delivered messages instead of being stored, so
the condition $|\mathit{Valid}| > 1$ becomes $\mathit{Val}_i = \{0,1\}$.
In the table $\mathrm{IN}\,b$, $\mathrm{EC}\,b$, $\mathrm{VT}\,v$,
$\mathrm{BD}\,v$ and $\mathrm{SL}\,v$ abbreviate the five message forms,
``mcast'' abbreviates the insertion of a message into the sender's
$\mathit{sent}$ pool, and a dash marks an unguarded rule.
The two $\mathrm{SEAL}$ rows and the SEAL-reading guards of the three return
rows are what D18 restores over the source blueprint's compressed four-round form, and carry
no separate marker in the table.

The four \textbf{wait until} blocks of Algorithm~\ref{alg:gbca-impl} are the
guards of \leandeclnamed{voteBit}{PLTS.ABA.GBCA.ImplStep.voteBit}/\allowbreak\leandeclnamed{voteBot}{PLTS.ABA.GBCA.ImplStep.voteBot},
\leandeclnamed{bindBit}{PLTS.ABA.GBCA.ImplStep.bindBit}/\allowbreak\leandeclnamed{bindBot}{PLTS.ABA.GBCA.ImplStep.bindBot},

$\mathit{sentEcho}$, $\mathit{sentVote}$, $\mathit{sentBind}$,
$\mathit{sentSeal}$ carry the ``not sent yet'' side conditions.
The three return rules are the three wait-until cases of the last block
verbatim: case (a) is an $n{-}f$ $\mathrm{SEAL}\,v$ quorum, case (b) an $n{-}f$
any-$\mathrm{SEAL}$ quorum containing $\mathrm{SEAL}\,v$ together with $f{+}1$
$\mathrm{BIND}\,v$ receipts and $|\mathit{Valid}| > 1$, and case (c) an $n{-}f$
$\mathrm{SEAL}\,\bot$ quorum with $|\mathit{Valid}| > 1$.
Each reads the receipts its own case names and nothing else, and case (c)
returns no bit.
The depth is what the grade-$1$ evidence buys (D18): $f{+}1$ $\mathrm{BIND}\,v$
receipts exceed the corruption budget, so they put an honest $\mathrm{BIND}\,v$
sender behind every grade-$1$ output, and that sender's own wait condition is an
$n{-}f$ $\mathrm{VOTE}\,v$ quorum over the write-once $\mathrm{VOTE}$ level ---
the object the binding argument of~\cite{ABDY22} counts.
The prose preceding Algorithm~6 in~\cite{ABDY22} says ``upon receiving
$\mathrm{echo4}$ messages from $2t+1$ parties'' where its own pseudocode says
$n - t$.
The two coincide only at $n = 3t+1$, and the encoding follows the pseudocode,
$n - f$.
The $dead$ and $grade$ fields of Transition System~2 are abstractions of these
receipt patterns and belong to the specification alone;
Theorem~\ref{thm:gbca-inst-refines} supplies them from the receipts.

The inventory above is monolithic.
It is a single automaton whose state is the whole system, so its rules may read
fields of processes other than the one they move: \leandeclnamed{deliver}{PLTS.ABA.GBCA.ImplStep.deliver} inspects the
sender's message pool and the receiver's row in one guard.
That the guards are nevertheless local is a property of the rules and not of
the state shape, and Definitions~\ref{def:aba-procnet}
and~\ref{def:aba-netadv} are where each of them is written against one node:
\leandeclnamed{deliver}{PLTS.ABA.GBCA.ImplStep.deliver} splits into the two halves of a $\mathrm{gdlv}$ rendezvous,
the network adversary supplying the pool guard $m \in pool(r,j)$ and the
receiver performing the row update.

\subsection{The round loop}

\input{nodes/def-aba-core}

The idle self-loop of a process carries \leandeclnamed{inputLoop}{PLTS.ABA.CoreStep.inputLoop} together with the Byzantine driver rules \leandeclnamed{callGByz}{PLTS.ABA.CoreStep.callGByz}, \leandeclnamed{retGByz}{PLTS.ABA.CoreStep.retGByz}, \leandeclnamed{callWByz}{PLTS.ABA.CoreStep.callWByz} and \leandeclnamed{retWByz}{PLTS.ABA.CoreStep.retWByz}, which fire at any phase for $id \in F$ and change no state (D11).
The step \leandeclnamed{retG}{PLTS.ABA.CoreStep.retG} sets $est$ to the grade, and \leandeclnamed{retW}{PLTS.ABA.CoreStep.retW} increments the round, adopts the coin when $est = \bot$, and multicasts $\langle\mathrm{DECIDED},b\rangle$ on an $A$-grade return (D10).
The DECIDED pool layer is three $\tau$-loops, round-agnostic because the pools carry no round index: \leandeclnamed{deliver}{PLTS.ABA.CoreStep.deliver}, by which the adversary moves a sender's pooled $\langle\mathrm{DECIDED},b\rangle$ to a receiver; \leandeclnamed{echo}{PLTS.ABA.CoreStep.echo}, the multicast on $f{+}1$ distinct receipts; and \leandeclnamed{byzDecided}{PLTS.ABA.CoreStep.byzDecided}, by which $id \in F$ pools either bit (D12$'$).
The exit \texttt{retABA}\,$id\,b$ fires once $n-f$ distinct senders of $b$ have been delivered to $id$ and $b$ is in $id$'s own sent pool.

The Lean encoding of Algorithm~\ref{alg:aba-core} is the system
$\mathrm{ABA.core}$, an LTS over the same label alphabet.
It is the round-loop control component only.
The two sub-protocols are separate systems, and the $\mathrm{callG}$,
$\mathrm{retG}$, $\mathrm{callW}$, $\mathrm{retW}$ steps of the core are pure
handshakes on the API labels.
Every rule is Dirac, so again the table needs no distribution column.

Each process carries a handshake phase, an element of
\[
  \mathrm{Phase} \;=\;
  \{\,\mathrm{idle},\ \mathrm{toCallG},\ \mathrm{awaitG},\ \mathrm{toCallW},\
    \mathrm{awaitW}\,\},
\]
traversed as
$\mathrm{idle} \to \mathrm{toCallG} \to \mathrm{awaitG} \to \mathrm{toCallW}
\to \mathrm{awaitW} \to \mathrm{toCallG} \to \cdots$.
There is no separate phase for the per-round bookkeeping between the WCC return
and the next GBCA call, because that bookkeeping is fused into the
$\mathrm{retW}$ step (D10).
The per-process record $\mathrm{ProcCore}$, \leandecl{PLTS.ABA.ProcCore}, has fields
\begin{itemize}
  \item $\mathit{input}$ --- the external input bit; unset before
    $\mathrm{callABA}$.
  \item $\mathit{est}$ --- the current estimate; the value $\bot$ is
    Algorithm~\ref{alg:aba-core}'s estimate awaiting the coin.
  \item $\mathit{round} \in \mathbb{N}$ --- the current round, counted from $0$
    (D9).
  \item $\mathit{phase} \in \mathrm{Phase}$ --- the handshake phase.
  \item $\mathit{lastGrade}$ --- the graded outcome of the current round's GBCA;
    unset before the return, and cleared by the round advance.
  \item $\mathit{returned}$ --- whether $\mathrm{retABA}$ has fired at this
    process.
\end{itemize}
The global record $\mathrm{CoreState}$, \leandecl{PLTS.ABA.CoreState}, has fields
\begin{itemize}
  \item $\mathit{procs} : [n] \to \mathrm{ProcCore}$ --- the control states.
  \item $\mathit{decidedSent} : [n] \to \mathcal{P}(\{0,1\})$ ---
    $\mathit{decidedSent}_j$ is the set of $\mathrm{DECIDED}$ payloads $j$ has
    multicast (D12$'$).
  \item $\mathit{decidedRecv} : [n] \times [n] \to \mathcal{P}(\{0,1\})$ ---
    $\mathit{decidedRecv}(i,j)$ is the set of $j$'s payloads delivered to $i$
    (D12$'$).
  \item $F$ --- the corrupted set, held in lockstep by the $\mathrm{fail}$
    broadcast.
\end{itemize}

  \#_i(b) \;=\; |\{\, j \in [n] \;:\; b \in \mathit{decidedRecv}(i,j) \,\}|

Only the five Byzantine driver rules test membership of $F$; the other ten
rules apply to corrupted and honest processes alike.
The return rule \leandeclnamed{ret}{PLTS.ABA.CoreStep.ret} is the notable case:
a corrupted process must pass the same $n - f$ quorum guard, exactly as in the
specification.
The corruption rule \leandeclnamed{fail}{PLTS.ABA.CoreStep.fail} is a synchronisation of every component of the
composition, each keeping its own copy of $F$.
The $\mathrm{est}$-update of \leandeclnamed{retW}{PLTS.ABA.CoreStep.retW} is Algorithm~\ref{alg:aba-core}'s
branch \textbf{if} $b = \bot$ \textbf{then} $b \gets c$, and the conditional
multicast is its branch \textbf{elif} $g = A$; the two are fused with the round
advance into one Dirac step (D10).
The \leandeclnamed{echo}{PLTS.ABA.CoreStep.echo} guard is payload-specific, matching
Algorithm~\ref{alg:aba-core}'s clause ``having not sent it'': a pool already
holding the other payload does not block the echo of $b$.

\dynamics{The round loop}{%
Each process runs a five-phase cycle: idle, ready to call the round's GBCA,
awaiting its return, ready to call the round's coin, awaiting the coin.
The graded outcome fixes the next estimate, an $A$- or $B$-return of value $b$
setting it to $b$ and a $C$-return clearing it to $\bot$; a cleared estimate is
filled by the coin of the same round, and a set estimate ignores that coin.
When the round's grade was $A\,b$, the step that receives the coin also
multicasts $\langle \mathrm{DECIDED}, b \rangle$ and advances the round.
A process holding $\langle \mathrm{DECIDED}, b \rangle$ from $f+1$ distinct
senders and not having multicast $\langle \mathrm{DECIDED}, b \rangle$ itself multicasts
$\langle \mathrm{DECIDED}, b \rangle$ itself, the $f+1$ threshold guaranteeing
one honest sender behind any echo.
The return rule requires $\langle \mathrm{DECIDED}, b \rangle$ from $n-f$
distinct senders together with the returning process's own prior multicast
of $b$.
The $n-f$ count is what excludes disagreement: two returns of different bits
would need two sender sets of that size, and any two such sets meet in more
than $f$ processes, hence in an honest one.
The own-multicast clause makes every return the endpoint of a diffusion its
own holder joined.
That an honest process never pools both payloads is not a property of the core
in isolation --- nothing in its rules forbids two $A$-grades of opposite bits in
different rounds --- but of the composition, where Graded Agreement on the GBCA
family rules that pair out; the core alone guarantees only that each process
returns at most once, by the flag its return rule sets.
}

The round-loop inventory is monolithic in the same sense.
Its \leandeclnamed{deliver}{PLTS.ABA.CoreStep.deliver} rule reads a sender's DECIDED pool and a receiver's row in
one guard, and the counts of \leandeclnamed{echo}{PLTS.ABA.CoreStep.echo} and \leandeclnamed{ret}{PLTS.ABA.CoreStep.ret} range over one
receiver's rows.
Definitions~\ref{def:aba-procnet} and~\ref{def:aba-netadv} write the same rules
against one node, the $\mathrm{ddlv}$ rendezvous splitting the soundness guard
$b \in dpool(j)$ at the network adversary from the freshness guard
$b \notin decIn(j)$ and the write at the receiver.

\subsection{The ABA specification and its safety}

The three specification systems locate the adversary differently from the
implementations they stand for.
An implementation pairs corruption-blind processes with an explicit
network-adversary PLTS, which owns the corrupted set together with its budget
and authorises every Byzantine action by the guard $k \in F$ of a component.
A specification carries no network component at all.
Its adversarial transitions are bare nondeterministic choices, resolved by the
scheduler: the Byzantine call fill and the total corruption rule of Transition
System~1, the adversary-chosen returns under $\top$ at Transition System~3, and
the disjunct $id \in F$ in the $F$-blind support counts of Transition System~2.
Leaving those choices unstructured is sound, because a specification constrains
from above.
An unstructured adversary makes the specification more permissive, never less.
Trace-distribution inclusion asks that every behaviour of the implementation be
matched by some resolution of the specification's nondeterminism, and the safety
theorems quantify over all such resolutions.
A specification adversary with more freedom therefore weakens neither
obligation.

The specification has six control states: \emph{unbound} ($bind = \bot$), \emph{bound} ($bind \neq \bot$, $coin = \bot$), \emph{coin differs} ($coin$ is the other bit or $\top$), \emph{coin agrees} ($coin$ is the bound bit), \emph{coin dead} ($coin = \dagger$), and \emph{decided} ($val \neq \bot$).
Rule 5 (\leandeclnamed{coinFlip}{PLTS.ABA.SpecStep.coinFlip}) is the branch out of \emph{bound}, and it is the only probabilistic transition of the system.
Its outcomes carry $\varepsilon$, $\varepsilon$, $1-2\varepsilon-\failmass$ and $\failmass$, so a resolution matches the bound bit with probability $\varepsilon$ and fails to deliver with probability $\failmass$ (D17).
On a match rule 6 (\leandeclnamed{adopt}{PLTS.ABA.SpecStep.adopt}) writes the bound bit into an empty honest slot and rule 7 (\leandeclnamed{repropose}{PLTS.ABA.SpecStep.repropose}) is disabled.
On a mismatch rule 7 is enabled and rule 6 is disabled.
On $coin = \dagger$ both are disabled, rule 6 because $\dagger$ agrees with nothing and rule 7 by its $coin \neq \dagger$ conjunct.
Rule 4 (\leandeclnamed{mixed}{PLTS.ABA.SpecStep.mixed}) binds under a quorum on both bits, with an $f{+}1$-support guard on the bound bit.
Rule 3 (\leandeclnamed{unanim}{PLTS.ABA.SpecStep.unanim}) writes $val \leftarrow\,!b$ when no honest process holds $b$.
Enabledness is wider than the control graph shows.
Rule 2 fires in every state, rule 3 is also enabled on \emph{coin differs}, and rules 3 and 5 to 8 remain enabled on \emph{decided}, where rule 3 rewrites $val$ to itself.
Rule 5 is enabled again on \emph{coin dead}, where the round is still reset and bound, and a second resolution is the only transition that leaves that state.
The provenance guards on rules 4 and 7 exclude the unanimity-overwrite (D3) and later-corrupted-input (D13) traces.

\medskip
\noindent\textbf{State.} The record \leandecl{PLTS.ABA.SpecState}.
\begin{itemize}

\[ s \xrightarrow{\;\tau\;} \delta\bigl(s[\,call[id] := bind\,]\bigr) \]

\[ s \xrightarrow{\;\tau\;} \delta\bigl(s[\,call[id] := b\,]\bigr) \]

No guard.

\noindent\textbf{10.} \leandeclnamed{callByzFill}{PLTS.ABA.SpecStep.callByzFill} (D13).
Guard $id \in F$ and $call[id] = \bot$.
\[ s \xrightarrow{\;\tau\;} \delta\bigl(s[\,call[id] := b\,]\bigr) \]

\noindent The guards on rules~4 and~7 are load-bearing.
Without the rule-7 guard the specification violates Agreement.
After a unanimous-$v$ round sets $val := v$ and a process returns $v$, an arbitrary re-proposal of $1-v$ lets rule~3 overwrite $val := 1-v$, and a second process returns $1-v$.
Without the rule-4 support guard the specification violates Validity.
At $n = 4$, $f = 1$ with inputs $1,0,0,0$ the value $1$ binds off its sole holder, that holder is then corrupted, and $1$ is re-proposed everywhere and decided, yet every never-corrupted process inputs $0$.

\dynamics{How a decision arises}{%
Which rule fires is scheduler nondeterminism, resolved by the adversary; the
coin is the only source of randomness.
The coin rule is enabled only on a round that is already reset and bound, so
the bound bit is committed before the coin resolves.
A coin outcome matching the bound bit has probability $\varepsilon$.
On such a match the re-propose rule is disabled, since its guard requires
disagreement, and a fresh call is disabled, since rule~1 requires the round
unbound.
Adoption, which writes the bound bit into the call slot, is then the only rule
that refills the slot of an honest process.
Corrupted slots may still be filled with either bit by the Byzantine fill rule,
but the unanimity rule's blocking condition quantifies over honest processes
only.
Once a quorum has spoken and no honest process holds the opposite bit,
unanimity is \emph{enabled}, never forced: the
scheduler may decline it forever.
No safety argument therefore uses $\varepsilon$, and the claim that the
protocol decides with probability $1$ under fair scheduling is a separate
liveness statement, not proved here.

With probability $\failmass$ the coin resolves to $\dagger$ instead, and the
round freezes.
The round is reset when the coin resolves, so every call slot is empty at that
point.
Adoption is disabled, since $\dagger$ agrees with nothing, and re-proposal is
disabled by its $coin \neq \dagger$ conjunct, so no honest slot is filled
afterwards either.
The Byzantine fill rule does not compensate: the quorum count
$|\{id \in [n]\setminus F : call[id] \neq \bot\} \cup F|$ counts a corrupted
process through $F$ whether its slot is filled or not.
That count therefore stays at $|F| \le f$, and $3f < n$ gives $f < n - f$, so
while the coin reads $\dagger$ neither the unanimity rule nor the mixed bind is
enabled, and the round produces no bind and no decision.
The freeze lifts only by a second resolution of the coin, rule~5 asking just
that the round be reset and bound, which a $\dagger$ outcome leaves true.
A single Byzantine fill closes that exit too, since rule~5 requires every call
slot to be empty.
}

\dynamics{Binding as negative information}{%
An instance binds by removing an option rather than by choosing one.
The only writer of $dead$ is \leandeclnamed{bindUnset}{PLTS.ABA.GBCA.Step.bindUnset}, which inserts, and it fires
from the empty set only, so $dead$ grows along every execution and one bit is
killed per instance.
Corruption does not touch the field.
Every property below is a consequence of that monotonicity together with the
membership guards on the returns, with no auxiliary invariant.
Both value-bearing returns carry the same guard pair, $v \notin dead$ and
$1-v \in dead$: the bit handed out is alive and the other bit is already dead.
That pair is Graded Agreement.
A return of $v$ pins $1-v$ into $dead$; monotonicity carries that membership to
every later state of the run; a later return of $w$ needs $w \notin dead$, so
$w \neq 1-v$, so $w = v$.
Two returns of one execution therefore name the same bit whatever their grades,
and once any value-bearing return has fired a single bit is the only one any
extension can ever hand out.
The $C$-return's guard $|dead| \ge 1$ is the Binding clause read on this state:
a member of $dead$ is a bit that no correct process is handed at grade $\ge 1$
in any extension, because the value-bearing returns refuse a dead bit and
$dead$ only grows.
A $C$-return therefore commits the instance --- from that point at most one bit
is alive anywhere in the future --- which is what makes handing out no bit the
right answer, and it is why every return, $C$-returns included, requires a kill
to have happened.
}

\dynamics{Why the kill is once-only}{%
The guard $dead = \emptyset$ on \leandeclnamed{bindUnset}{PLTS.ABA.GBCA.Step.bindUnset} is what keeps every round
completable.
Let us see what a second kill would cost.
Suppose the rule were enabled again after an $A$-return of $v$, and fired on
$v$ itself.
The processes yet to return would then have no return available: the
value-bearing returns need a live bit, and there is none, while the $C$-return
is blocked by the $A$-latch.
The round would be stranded, and a fair scheduler could not complete it.
Under the once-only guard no such state is reachable.
A round that has answered one process at grade $\ge 1$ can answer every other
process the same way, since the surviving bit stays alive and the $A$-latch
admits further $A$- and $B$-returns.
}

\dynamics{What the contract asks and what is proved here}{%
The GBCA contract listed at the start of this case study has four clauses.
The specification instance settles two of them outright and the safety half of
a third.
Graded Agreement is the guard pair on the value side and the grade latch on the
grade side, both structural (Theorem~\ref{thm:gbca-spec-binding}).
Binding is the $C$-return guard read through monotonicity, again a theorem of
the same statement.
Validity has a safety half, that under unanimous honest input $v$ every return
of the instance hands out $v$ and no $C$-return occurs, and that half is
Theorem~\ref{thm:gbca-spec-validity}.
What the clause asks beyond that half --- that the grade is the top one, and
that every correct process is answered at all --- is a statement about which
runs the scheduler must extend, as is Termination.
Fairness is not encoded here, so those clauses lie outside this development.
}

\dynamics{What the grades promise}{%
The grade records how much of the round its holder is committed to.
An $A$-return commits to the surviving bit and is the grade that licenses a
decision.
A $B$-return carries the surviving bit as the next estimate but records that
dissent was seen.
A $C$-return carries no value, and its holder falls back on the coin.
The $A$- and $C$-latches are mutually exclusive: once an $A$-return has
occurred no $C$-return is enabled at that instance, and once a $C$-return has
occurred no $A$-return is.
The kill, the dissenting bit at a $B$-return and each of the two bits at a
$C$-return are gated on $f+1$ distinct supporters, counted $F$-blind, so the
count is monotone in $F$ and immune to later corruptions.
At most $f$ processes are ever corrupted, so any such set of $f+1$ contains a
member outside the final corrupted set, hence a never-corrupted genuine caller.
That member is the witness which carries Validity down to a caller: a bit $v$
handed out at grade $\ge 1$ requires $1-v \in dead$, and the kill that put it
there certified $f+1$ $F$-blind supporters of $v$ itself.
}

\dynamics{The coin and its parameters}{%
One coin resolution has four outcomes.
With probability $\varepsilon$ the outcome is the bit $0$, and with probability
$\varepsilon$ it is the bit $1$.
In either case every correct process receives that bit.
With mass $1 - 2\varepsilon - \failmass$ the outcome is $\top$, the unresolved
coin: each process may then be handed either bit by the adversary,
independently of the others.
With probability $\failmass$ the outcome is $\dagger$, on which the resolution
delivers to no process at all (D17).
The outcome $\dagger$ models a delivery failure of the implementation this
specification stands for.
That implementation reconstructs the coin from an $\varepsilon$-correct
verifiable secret sharing, and the reconstruction can fail; on failure the coin
delivers nothing.
The two non-bit outcomes are distinct at the interface.
On $\top$ the coin delivers, and the adversary only picks which bit each
process receives.
On $\dagger$ no delivery occurs, and the callers of that instance hold no
return to read.
Transition System~3 is a specification, not an implementation.
The $\varepsilon$-Goodness it asserts is an assumption of this development, to
be discharged by an implementation over Gather and SRSD that is not modelled
here.
The assumption is inert for the results proved: safety holds for every
admissible pair $\varepsilon, \failmass$, including $\varepsilon = 0$, where the
coin resolves to $\top$ or $\dagger$ almost surely.
Safety is insensitive to $\failmass$ for a further reason: the outcome $\dagger$
removes returns rather than adding any, and every safety property of this
development constrains the returns that do occur.
It is a termination argument that would consume the $\varepsilon$-mass, and
such an argument must carry the $\failmass$-mass too, since a $\dagger$ resolution
produces no return at all.
Termination and fairness are out of scope.
}

subsystem of the deployed protocol, then to the family of rounds, and then
into the deployed composition.

\subsection{The exploded presentation}

A sub-protocol may be replaced by its specification where it is a component of
a composition, and nowhere else.
The deployed protocol of Definitions~\ref{def:aba-procnet}
and~\ref{def:aba-netadv} does not present the graded-agreement layer as a
component.
Each program runs two layers at once --- its round loop and one stage record
per round --- and the single network adversary holds the message pools of both
layers.
This subsection re-cuts the same system so that a layer boundary is a
component boundary, and Theorem~\ref{thm:aba-exploded-atd} states that the
re-cut is exact in both directions.

The cut is decided by one question: which network does a factor own?
A round of graded agreement is a replaceable factor exactly when the round's
message fabric belongs to that factor --- the pools its stage messages sit in,
the guard that lets one be delivered, and the injections a corrupted sender
makes into it.
The subsystem of Definition~\ref{def:aba-gbcasub} is drawn to own it.

\dynamics{What the idealisation removes and what it leaves}{%
The substitution replaces one factor, and the factor is a round of graded
agreement together with that round's message fabric.
Everything the fabric holds goes with it.
The stage pools disappear, and with them the guard $m \in pool(j)$ that made a
delivery sound, the write-once slots that recorded a multicast, and the
injection $\mathrm{byzG}$ by which a corrupted sender put an arbitrary stage
message into circulation.
The round specification has none of these: it has call slots, an exclusion set,
and graded returns.
What survives is everything the other three factors hold.
The DECIDED layer keeps its own pools, its own delivery guard and its own
Byzantine injection, at the ABA-side network.
The corrupted set survives there too, with the budget $|F| < f$ as the guard on
the $\mathrm{fail}$ row, and so does the authorisation $k \in F$ of every
Byzantine drive --- including the drives of the graded-agreement handshake,
whose effect is inside the replaced factor and whose authorisation is not.
The asymmetry is decided by the cut and not by the argument: a Byzantine power
vanishes under an idealisation exactly when it is a power over the network the
idealised factor owns.
This also fixes what it would take to vary the network's power.
A weaker message fabric --- lossy delivery, a bound on injection, authenticated
channels of a different strength --- is a different system in the same slot,
and it enters the chain by the same precongruence, with the round loops, the
DECIDED layer, the corrupted set and the coin oracle untouched.
The strength of the network is a modular axis of the development rather than a
property woven through it.
}

\subsection{From the deployment-shaped specification to the ABA specification}

The simulation onto the ABA specification is hand-built, and it is written
against the monolithic round loop rather than against $n$ round-loop programs
beside a network.
The proof therefore repartitions state first, carrying the deployment-shaped
specification onto a monolithic composition, and runs the simulation from
there.
Assembling $n$ nodes and a network into one record loses the distinction
between states that differ only in how the same data is distributed, which is
why the repartition is an inclusion and not an equality.

\dynamics{What the simulation buys}{%
The abstract twin of a state of that composition is lazy.
Every hidden row is answered by a stutter: the handshakes, the internal steps
of the sub-protocol specifications, and the delivery and echo of DECIDED all
leave the twin where it was.
The probabilistic coin row is answered the same way, under the constant
coupling that sends every outcome of the flip to the one unchanged twin, so the
twin never fires its own coin rule.
The entire decision is deferred to the first visible return, where a single
weak step binds, clears the call row and writes the decision value before the
return label is emitted.
The payoff comes from the soundness theorem for probabilistic forward
simulation: every achievable trace distribution of the deployed protocol is an
achievable trace distribution of the specification.
A safety property proved of the small specification therefore holds of every
trace of positive probability in the protocol as it runs.
}

\subsection{The main theorems}

Three steps separate the deployed protocol from the ABA specification:
\[
  \mathrm{netFlat}(P)
  \;\overset{\text{(1)}}{=}\; \mathrm{exploded}(P)
  \;\overset{\text{(2)}}{\sqsubseteq}\; \mathrm{flatSpec}(P)
  \;\overset{\text{(3)}}{\sqsubseteq}\; \mathrm{spec}(P),
\]
where (1) is the regrouping of Theorem~\ref{thm:aba-exploded-atd}, exact in
both directions; (2) the substitution of
Theorem~\ref{thm:aba-substitution}; and (3) the refinement of
Theorem~\ref{thm:aba-flatspec-spec}, itself a repartition of state followed by
the core simulation.
The subject of the chain is the system as deployed.
No step of it leaves the deployed vocabulary for the sake of the argument: (1)
and (2) are read in deployment coordinates throughout, and only the proof of
(3) leaves deployment coordinates, for the composition the hand-built
simulation is written against.
